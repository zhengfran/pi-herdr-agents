# Jev routing: offline synthetic calibration scaffolding (T11)

**Uncalibrated. Not live Jev quality, service latency, model access, or a promotion gate.** These fictional exact tuples, redacted/invented tasks, distributions, timings, tokens, and host decisions exercise mechanical contracts only. No achieved quality target is asserted. Tier/family names are administrator-style synthetic labels, not inferred capabilities or independence guarantees.

## Run

From the repository root with its existing development dependencies and a Node version supporting type stripping:

```bash
node --experimental-strip-types --test test/evals/jev-routing-*.test.mjs
npm run test:eval:jev-routing
# Same two commands as the dedicated script:
node --experimental-strip-types test/evals/jev-routing-validate.mjs
node --experimental-strip-types test/evals/jev-routing-score.mjs
```

The CLIs take **no arguments** and read only the four checked-in fixtures. The validator prints a JSON summary; the scorer prints a JSON report. Invalid schemas, bindings, distributions, or bounds exit nonzero. The validator also rejects semantic/safety violations. The scorer keeps structurally valid host mistakes visible in `violations` and metrics, and exits nonzero if any exist. Its programmatic `scoreBundle(bundle)` returns the report for mutation tests instead of throwing on semantic disagreements; structural corruption always throws.

`npm test` already includes `test/evals/*.test.mjs`, so neither a duplicate test invocation nor live evaluation is added there. The dedicated script only validates/scores; it does not contact Pi's model registry, TypeSafe, a provider, or credential storage. `npm test` and integration must never call live Jev. The existing production **pure** question builders, decoder, and combination policy are replayed offline; no input handler or launcher is executed.

## Files and strict schema

All objects have exact keys; unknown/missing keys, bad types, nonfinite values, invalid bounds and duplicate IDs fail closed. Nothing is truncated, renormalized, filled in, or guessed. The main exported seams are `loadBundle`, `validateBundle`, `scoreBundle`, `bindingFor`, `digest`, and `replay`.

- `test/fixtures/jev-routing/catalog.json`: `version`, `synthetic:true`, `thresholdsStatus:"uncalibrated"`, `roles`, `tuples`. Four roles define exact `id`, `agent`, `intent` (`report`/`modify`), `purpose` (`task`/`review`), `responsibility`, `deliverable`, `excludes`. Twenty tuples define **all** of `id`, `roleId`, `harness`, `model`, `effort`, `tier`, `family`. IDs are opaque `rNN`/`cNNN`; tuple identity/authorization includes every field, not merely an ID or model name. Pi refs and native IDs are separate namespaces. These fictional Pi/Claude tuples cannot establish authentication or authorize a real launch. Profile text is synthesized locally by `snapshotFor`; preference is catalog order. Both are fixed by the evaluator version and catalog digest, not remotely supplied.
- `cases.tune.json` and `cases.heldout.json`: `version`, `split`, `cases`. Each case contains `id`, `version`, `language`, `categories`, `task`, `view`, `scenario`, `expected`.
  - `view`: `mode` (`tui`/`rpc`/`json`/`print`), `source` (`interactive`/`rpc`/`extension`), `streaming` (`null` means absent, otherwise `steer`/`followUp`), `images` (count), booleans `enabled`, `apis`, `persisted`, `herdr`, `child`, `idle`, `pending`. This is an explicit synthetic current-view admission subset, **not** a replacement for production eligibility/privacy screening or lifecycle tests. Full session/config/candidate safety remains covered by T01–T10.
  - `scenario`: `stable`, `candidate-drift`, `crash-before-ownership`, `dispatch-unknown`. Drift represents a failed whole-set revalidation, not permission to reclassify. Crash-before-ownership has no completed evidence and unknown execution/recovery; dispatch-unknown has a selected tuple but no positively known dispatch receipt. Neither implies zero work or permits replay. These are annotated synthetic scenarios, not reconstructed crash observations.
  - `expected`: `kind` (`route`/`abstain`/`bypass`/`unknown`), `reason` (null for route), acceptable `roles` and `tupleIds`, `minBand` (0–3), `mutation` (`report`/`modify`/`unspecified`), `maxTier` (nullable ceiling for unnecessary-frontier accounting), `independence`, nullable `authorFamily`, `authorization:"exact-catalog-only"`, `noReplay:true`. Independence values are `none`, `strict-known-author`, `strict-unknown-author`, `review-provenance-unverified`. Known-author labels annotate the task description only: user prose is not trusted provenance. Review-purpose roles abstain in v1 even when prose names an author; strict review is not auto-launched. Minimum tier follows the pinned policy: fast/mid/frontier/frontier for bands 0/1/2/3. These are policy buckets, not portable token budgets.
- `answers.synthetic.json`: `version`, `synthetic:true`, `records`; exactly one record per case. Each has `caseId`, unique package-local `decisionId`, `binding`, `batches`, `host`.
  - `binding`: exact `pin`, `policy`, `questions`, `catalogVersion`, `catalogSha256`, `caseVersion`, `caseSha256`, `split`. SHA-256 covers canonical sorted-key JSON of the complete catalog/case, including expectations and view. This prevents accidental fixture/version drift, not malicious edits to both data and digests. The exact shipped pin is `jev-1.13.0`, questions `jev-auto-questions-v1`, policy `jev-auto-v1`.
  - `batches`: `A` and `B`, each null or `{wire, telemetry}`. `wire` is the complete pinned `{model, answers, usage}` response. Every Choice has all offered `probabilities`, maximal `choice`, `confidence`; every Score has all four probabilities, exact rubric `legend`, consistent mean `score`, `confidence`; Noul has `type` and `noul`. Full key sets, sums (production tolerance 1e-6), ranges, confidence and mean/legend are validated by the production decoder. Batch B options are rebuilt from Batch A distributions, including effort/tier filtering. B is forbidden after A abstention; both are absent for bypasses. The evaluator synthesizes the public adapter's lossy normalized result only to exercise its observation contract; it never drops wire distributions from scoring.
  - `telemetry`: `latencyMs`, nullable `inputTokens`, nullable `outputTokens`, nullable `costUsd`. Known token counts must agree with the wire. Null means unavailable/unpriced, **not zero**. Synthetic adapter cost placeholders do not become priced telemetry. Maximums: latency 60,000 ms, tokens 1,000,000 each, cost $1,000 per batch, wire 64 KiB.
  - `host`: `kind`, nullable `reason`, nullable `candidateId`, nullable full `tuple`, nullable `requiredBand`, `dispatches` (array of full known tuple receipts), `dispatchState` (`known`/`unknown`). A route requires exactly one matching known authorized dispatch; abstain/bypass require none. Unknown means actual dispatch cannot be inferred; known receipts remain empty in these crash fixtures. Repeated dispatch is checked **within one local decision only**.

Case text is bounded to 8 KiB; role profiles to 256 bytes; roles/tuples to 16/128; cases to 256 per split; records to 512. Distribution validation uses the existing production bounds and question builders. Arbitrary external captures are deliberately not accepted by these CLIs; any separate capture format or adapter needs its own review and consent.

## Tune versus held-out

Tune has **34** cases; held-out has **63**. IDs, record IDs and decision IDs are unique, with mechanically disjoint splits. The validator also rejects an identical `(task, current view, scenario)` in both splits even if renamed. Identical inputs **within** held-out are intentional separate decisions, not deduplicated submissions.

Use tune only for question/policy/profile exploration. Freeze exact versions/catalog/expectations before examining held-out results. Never tune on held-out answers, move failed held-out examples into tune while retaining the same evaluation claim, or report pooled synthetic accuracy as independent held-out quality. Split reports are emitted separately; the aggregate is explicitly only a mechanical summary. Content fingerprint checks cannot prove absence of semantic paraphrase leakage: human curation is still required. Question/policy changes require new versions and a new frozen comparison; fixture hashes alone are not calibration.

The corpus covers seven language tags (`en`, `es`, `zh`, `fr`, `de`, `ja`, `ar`), code/log quotations, local file references, inspect-to-implement and unread-source clear targets, ambiguous pronouns, natural-language pinned runtime/model requests, capability-widening injections and quoted injections, report versus artifact-writing plans, known/unknown-author review, low-reasoning/high-consequence tasks, bimodal and low-confidence evidence, whole-set drift, current-view transforms/expanded files, removed-upstream-image scenarios, all 35 noneligible mode/source/streaming combinations, repeated identical input, crashes and uncertain dispatch.

## Current-view TUI contract and privacy limits

Only idle, top-level TUI/interactive input with absent streaming behavior and no **current** images can be eligible. RPC/JSON/print, extension-source and streaming input bypass without classification or launch. Eligibility also depends on current local safety checks. The package sees only this handler's text/images after preceding transforms. Expanded `<file>` text is current prompt data; it does not authorize reading additional files for egress. An image removed by an earlier extension is unobservable and does **not** force a bypass. Categories describing the synthetic upstream setup are evaluator annotations, not public original-submission metadata. No task/receipt attests original editor text, physical ingress, host submission identity, first/last extension ordering, or reliable idle Escape cancellation.

Repeated identical current inputs are distinct package decisions. No distribution fixture, latch or decision ID proves host-submission deduplication, atomic persistence-plus-dispatch, or cross-process exactly-once execution. Crash/unknown work requires explicit recovery inspection, never automatic replay or interpreting unknown as no work. Strict review needs the parent/manual trusted-provenance workflow, not author-family inference from model names or prompt text.

This task adds **no live capture command or consent shortcut**. Any separate live evaluation/capture requires explicit informed egress approval for the precise current prompt and reviewed profiles, exact pinned versions, a reviewed privacy/retention plan, and frozen splits. Never collect raw private prompts, credentials, role bodies, repository history or captures implicitly from normal input. Redact before approved capture; screening does not guarantee secrecy or vendor zero retention. Generated captures/reports belong **outside the repository and package**. These invented fixtures are not telemetry collected from users. Tests are normally excluded by `.npmignore`; no packaging override ships these fixtures/evaluators.

## Output and denominators

The dedicated command prints a validator summary (`97` cases, `0` violations) followed by the scorer report with `evidence`, `thresholdsStatus`, `versions`, `denominators`, `aggregate`, `splits`, `violations`.

- Route coverage = eligible host-routed decisions / all eligible decisions, including unknowns; bypasses are not abstentions.
- Conditional role accuracy, exact tuple accuracy and under-tier rate use eligible host-routed decisions only. Tuple accuracy requires an acceptable authorized tuple and agreement with the full-distribution policy decision/dispatch. Role accuracy checks the labeled acceptable role set.
- Unnecessary top-tier rate uses routed decisions with a non-null labeled tier ceiling; it counts frontier selections where frontier is unnecessary. It is not a price optimizer or proof of an optimal model.
- Abstention reason counts exclude bypass/unknown outcomes; bypass reason counts are separate. Unauthorized launches count **known** dispatch receipts. Repeated dispatch reports affected local decisions, excess known dispatches and maximum known dispatch count. `unknownDispatchDecisions` prevents zero known violations from being misread as proof of no unknown work.
- Language/category disagreement uses all cases carrying each label; multi-category cases contribute once per category. `policyAgreement` replays full distributions and compares the host result. All rates include numerator/denominator; empty denominators yield null.
- Latency percentiles use nearest-rank on **each completed A+B sum**, not a sum of batch percentiles. Report includes sample/excluded counts and excludes ownership/launch time. Token/cost availability covers completed classifier batches, not child execution: sample/available/unknown counts, known subtotal, and total (null unless every sample is known). An empty sample also has null totals/percentiles.

Current synthetic mechanical output: **50 eligible, 25 routed, 21 eligible abstentions, 47 bypasses, 4 unknowns**. Role and tuple accuracy are 25/25, under-tier and unnecessary-frontier counts 0/25; zero known unauthorized/repeated dispatches, four unknown-dispatch decisions. Completed A+B latency has 30 fictional samples: p50/p95/p99 = **47/57/59 ms**. Of 78 completed batches, all token telemetry is available (9,064 input and 2,040 output tokens); cost is known in 12 (synthetic zero values) and unpriced in 66, so total cost is **null**, not $0. Tune routes 12/22 eligible; held-out routes 13/28 eligible. **These numbers only establish deterministic fixture consistency; all thresholds and quality remain uncalibrated.**
